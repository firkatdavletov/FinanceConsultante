# FinanceConsultante — контекст проекта

Дата исходного описания: 2026-09-06.

## Для кого и зачем

Личный Telegram-бот владельца для понимания расходов, учёта доходов, планирования накоплений и развития семейного бюджета. Основной интерфейс — короткие сообщения на русском языке. В первой версии владелец ведёт общий семейный бюджет сам; совместный ввод членами семьи добавляется отдельным этапом.

## Пользовательские сценарии

| Ввод / событие | Ожидаемое поведение |
| --- | --- |
| `супермаркет 15000` | Расход 15 000 в категории «Продукты», запись в БД и подтверждение с возможностью исправить или отменить |
| `продукты 700` | Расход 700 в категории «Продукты» |
| `аптека 1300` | Расход 1 300 в категории «Здоровье» |
| `зарплата 1300000` | Доход 1 300 000 в категории «Зарплата» |
| Неоднозначное сообщение | Уточнение; до ответа деньги не меняют баланс |
| Каждое утро | Учётный баланс, рекомендуемый лимит на сегодня, оценка бюджета и краткая рекомендация |
| Раз в неделю / месяц | Расходы и доходы за завершённый период, категории, сравнение и рекомендации |
| Планируется крупная покупка | Сценарий покупки с влиянием на обязательные платежи, остаток и цели накоплений |
| Регулярные расходы | Учёт предстоящих платежей, анализ динамики, рекомендации и прогноз |

Бот учитывает введённые пользователем операции. Он не знает банковский остаток без начального баланса и полного учёта движений. На старте это явно объясняется пользователю.

## Рабочие предположения

Подтверждённые владельцем 2026-09-06 настройки: основная валюта `KZT`, дополнительная `RUB`, часовой пояс `Asia/Almaty`, утренний отчёт в `08:00`. Финансовые суммы владельца ещё не заданы.

- Язык — русский. Доходы и расходы допускаются в `KZT` и `RUB`; баланс и итоговые отчёты рассчитываются в `KZT`.
- Ежедневно нужен снимок курса `RUB/KZT`: сколько `KZT` стоит `1 RUB`. У рублёвой операции сохраняются исходная сумма, курс на местную дату операции и оценка в KZT; новый курс не переоценивает историю. При отсутствии курса запись ожидает его получения. В T02A реализован источник Currencylayer `/live` и персистентный загрузчик.
- Один владелец, один бюджет, один сводный счёт с начальным остатком в KZT. Отдельные карты, счета, валютные остатки и реальные обменные переводы за пределами MVP.
- Расчётный период — календарный месяц; утренний отчёт — 08:00 местного времени, недельный — в понедельник, месячный — первого числа, также в 08:00.
- Начальный остаток, дата начала учёта, регулярные платежи, резерв, доходы и цели задаются владельцем. Их нельзя выводить из примеров сообщений.
- Простой однозначный ввод записывается сразу с кнопками исправления и отмены. Неоднозначный ввод и результат LLM в MVP сначала подтверждаются владельцем.
- OpenAI — опциональное улучшение. Основной учёт и числовые отчёты работают при отключённом API.

## Функциональные границы

Первый рабочий релиз: защищённый вход, настройка бюджета, запись и исправление доходов/расходов, категории, баланс, регулярные обязательства, ежедневные рекомендации, недельная и месячная аналитика, хранение и резервное копирование.

После первого релиза: накопления и цели, анализ крупных покупок, поиск повторяющихся расходов, расширенный прогноз, совместный семейный ввод. Учёт накоплений входит в общий замысел и имеет отдельные задачи в плане.

Не входит в текущий план: банковские интеграции, автоматическое перемещение денег, инвестиционная торговля, OCR чеков, голосовой ввод, публичный SaaS, веб-интерфейс и валюты кроме KZT/RUB.

## Фактическое состояние

На 2026-09-08 настроен каркас с Kotlin `2.3.21`, Spring Boot `4.1.1`, Java toolchain `17` и Gradle Wrapper `9.5.1` с SHA-256. В `check` включены ktlint `1.8.0` (плагин `14.2.0`), Detekt `2.0.0-alpha.3`, отдельный `integrationTest` и отчёт JaCoCo `0.8.15`. Spring smoke-тест входит в интеграционный набор и проверяет отключение внешних интеграций; unit-набор покрывает деньги, курсы, настройки и баланс.

Есть профили `local` / `test` / `prod`, `.env.example`, правила исключения секретов, README и GitHub Actions workflow. В завершённой T02 добавлены Compose для PostgreSQL 17.11, JDBC/Flyway, начальная схема бюджета/владельца/счёта/категорий/проводок/аудита и ежедневных курсов. Денежная модель проверяет точность и диапазон, хранит оценку RUB-операций в KZT; application-сервис атомарно записывает проводку и аудит с уникальностью источника. Баланс учитывает только проведённые операции и сохраняет отрицательный результат.

В T02A выбран Currencylayer `/live`: из USD-котировок детерминированно рассчитывается `USDKZT / USDRUB`, сохраняются время котировки/получения и код происхождения. Персистентные задания создаются на 07:00 Asia/Almaty для каждого календарного дня, включая выходные; lease, retry и восстановление после простоя защищают от повторов и зависших worker. HTTP выполняется вне транзакции фиксации, а существующий дневной снимок не перезаписывается. Для пропущенной либо явно запрошенной прошлой даты выбранный live endpoint даёт первый снимок после восстановления с честными timestamps, а не ретроспективную котировку. Ключ читается только из `CURRENCYLAYER_ACCESS_KEY`; загрузчик выключен по умолчанию и принудительно отключён в Gradle-тестах.

Docker Desktop установлен. Итоговый `./gradlew --no-daemon --no-build-cache clean check bootJar` после T02A прошёл с реальным Testcontainers: 34 unit-теста и 38 интеграционных тестов без ошибок/пропусков; ktlint, Detekt, JaCoCo и JAR успешны. Ранее отдельно проверены Compose, сохранность схемы после перезапуска и запуск JAR с local/prod. Currencylayer проверен на локальном WireMock; живой API с пользовательским ключом не вызывался. OpenAI-адаптеры, планировщик отправки отчётов и контейнеризация приложения ещё отсутствуют. Git remote не настроен, поэтому GitHub Actions ещё не запускался.

В T03 реализованы Telegram Bot API через RestClient, long polling и PostgreSQL inbox/offset/outbox с lease, обработкой повторов и восстановлением после сбоя. Только настроенный владелец в private chat может читать и менять бюджет; проверка выполняется до сохранения текста и повторно перед обработкой и доставкой. Команды `/start`, `/help`, `/settings` и редактирование остатка/даты, времени отчёта и резерва сохраняют состояние диалога в БД. Первичная настройка атомарно создаёт бюджет после последнего ответа; `/cancel` отменяет черновик. Основная KZT и Asia/Almaty фиксированы, исходное время 08:00 подтверждается владельцем. После появления проводок начальный остаток/дата неизменяемы; резерв не создаёт расход. Обработанный входящий текст удаляется сразу. Доходы/расходы через Telegram добавлены в T05; отчёты пока не отправляются.

Итоговый `./gradlew --no-daemon --no-build-cache clean check bootJar` после T03 успешен: 63 unit-теста и 53 интеграционных теста без ошибок/пропусков, с настоящим PostgreSQL/Testcontainers; ktlint, Detekt, JaCoCo и JAR прошли. Telegram проверен через локальный WireMock, включая сквозной сценарий с БД, timeout/429 и неоднозначную доставку. Telegram выключен по умолчанию, реальные API/регистрация/ручная отправка не выполнялись. Поля token/owner задаются окружением; инструкции запуска и ограничения доставки находятся в README.

В T04 добавлен независимый от Spring и сети `TransactionMessageParser`: короткий ввод и явные `/expense` / `/income`, точные суммы KZT/RUB, начальный словарь категорий «Продукты», «Здоровье», «Зарплата» и даты. Результаты разделены на предложение операции, вопрос о покупке, команду и уточнение с причиной. Неоднозначный ввод, неизвестные категории/валюты, несколько операций, переносы строк, некорректные суммы и будущие даты не становятся предложением фактической проводки. Синтаксис описан в `/help` и README. Связывание parser с Telegram inbox, категориями бюджета и записью выполнено в T05.

Итоговый `./gradlew --no-daemon --no-build-cache clean check bootJar` после T04 успешен: 196 unit-тестов, включая 133 проверки parser, и 53 интеграционных теста с настоящим PostgreSQL/Testcontainers без ошибок/пропусков; ktlint, Detekt, JaCoCo и JAR прошли. Реальные внешние API не вызывались.

В T05 связан inbox → parser → use case → ledger/audit → outbox. После настройки однозначный ввод создаёт проводку и подтверждение; `/balance` показывает баланс и обороты в KZT, `/history` — страницы по 10 записей с устойчивым курсором. Неоднозначный ввод сохраняет `TransactionDraft`; последующий полный ввод уточняет его, а `/confirm <id> <версия>` проводит один раз с исходным финансовым источником. `/draft` восстанавливает уточнение после рестарта, `/cancel` отменяет незаписанный черновик. Полный текст обработанного inbox удаляется; черновик хранит только структурированные поля.

Операция использует местный день исходного Telegram-сообщения, включая обработку после простоя; дата до начала учёта требует явного решения владельца. Миграция V4 сохраняет данные V3, а старый inbox без даты просит повторить ввод. RUB без курса сохраняется в черновике и ставит дневную загрузку в очередь; после получения курса требуется подтверждение. Проводка, аудит, состояние черновика, результат inbox и ответ outbox атомарны. Сбой доставки может продублировать ответ, но не финансовую операцию. Исправления записанных операций, кнопки и callback остаются T06.

Итоговый `./gradlew --no-daemon --no-build-cache clean check bootJar` после T05 успешен: 201 unit-тест и 68 интеграционных тестов без ошибок и пропусков, с PostgreSQL 17.11 через Testcontainers; ktlint, Detekt, JaCoCo и JAR прошли. Telegram проверен только через локальный WireMock, живой API и пользовательские финансовые данные не использовались.
