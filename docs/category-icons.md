# Коды иконок категорий

Сервер хранит `Category.icon` / `category.icon_code` как произвольную непустую строку.
Это непрозрачный идентификатор клиентского изображения, а не серверный enum. Код
сохраняется без trim, изменения регистра или проверки по набору Android-ресурсов.
Создание и изменение категории, bootstrap/import и журнал sync v4 поддерживают
неизвестные серверу коды, например `custom.icon-v2`. Отсутствующий обязательный код
и пустые/пробельные значения отклоняются. Отсутствующий код в частичном обновлении
сохраняет прежнее значение.

V28 удаляет только прежнее CHECK-ограничение списка кодов, оставляя TEXT NOT NULL,
значение по умолчанию OTHER и все имеющиеся категории. Применённые миграции не меняются.
Новые изображения после V28 не требуют обновления схемы, сервера или версии протокола.

Форма JSON сохранена: команды используют строковое поле `icon`, ответы категорий —
`icon.code`, синхронизация — `iconCode`. Устаревшие `icon.emoji` и `iconEmoji` содержат
общий символ `📦`. Современный Android игнорирует эти поля, выбирает PNG по коду
и показывает запасное изображение для неизвестного кода, не заменяя сам код.
Telegram хранит собственные прежние варианты выбора в слое представления;
неизвестным кодам соответствует `📦`.

Сначала требуется выпустить сервер с V28, затем клиент с новыми PNG. Развёртывание
в эту правку не входит. Проверки используют синтетические данные и PostgreSQL/Testcontainers:
миграция V27→V28 и пустой БД, bootstrap, import, команды, чтение и sync неизвестных кодов,
а также запрет пустого кода. Реальные внешние API и production-данные не используются.
